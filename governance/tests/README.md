# Governance tests — prototype exercises
**Parent:** [governance](../README.md) · **Status:** verification design (not a completed test suite).
Cases: challenge a rule from any role; contest a closed issue; test director approval vs peer comment; revise a delegation and search dependent resources; preserve an earlier legal action; send an issue to the wrong department; reviewer rejects unsupported architecture change. Each executed result should have commit SHA, inputs, observed output and limitations linked from an Issue or PR.

Structural and template tests are implemented in [operations/tests](../../operations/tests/README.md). No governance integration test is presumed to pass merely because this README exists.
Maintenance: add or revise cases when a governance decision changes; do not erase failed observations.
