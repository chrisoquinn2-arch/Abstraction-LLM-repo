# Review and amendment lifecycle — candidate for prototype exercise
**Status:** proposed; no binding effect without authorized adoption. **Primary authority:** Charter Articles VII and X.

## Entry
A participant locates the affected rule via root and department README; opens a **challenge** Issue in [Forum](../../forum/README.md) or proposes a file change via PR. State exact instrument, current version or commit, proposed effect, reasons, evidence, unresolved objections, anticipated dependents and request.

## Responsible roles
1. **Executive** acknowledges receipt and routes to a competent Governance role; wrong-domain intake remains open and transferable, not rejected.
2. **Governance** classifies ordinary clarification vs consequential amendment vs charter amendment; evaluates alternatives, grounds, dependencies and dissent. Do not let a reviewer confer itself greater authority.
3. **Review** is independent when charter or approved subordinate rule requires it. A GitHub review comment alone is not a lawful approval unless review authority and scope are recorded.
4. **Application**: implement only after appropriate approval; link decision, affected PR, effective date, old/new rule version, impacted dependents and owner of reconciliation.
5. **Propagation**: operations/executive/research assess affected skills, roles, live tasks, prior conclusions and indexes; mark blocked items or obtain reauthorization. Report incomplete reconciliation openly.

## Mandatory distinctions
A forum reply is not an amendment. A PR merge is not proof of legitimate enactment. A historical action valid at the time remains historically valid unless governing law says otherwise. A dissenting minority opinion is not erased by a resolution. Any part of this procedure itself can be challenged.

## Prototype evidence to collect
A challenged rule, a rejected change, an accepted exercise change, a revoked delegation mid-task, a misleading older README, an independent reviewer, and a human review packet with traceable sources. This document is the process hypothesis to be tested, not an assertion of execution success.
