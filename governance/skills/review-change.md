# Skill: Review a consequential governance change
**Status:** prototype candidate. **Use when:** a proposed change affects a standard, role authority, delegation or constitutional interpretation.
**Inputs:** charter and currently effective version; proposed diff/issue; rationale, alternatives, affected resources, evidence and authority of reviewer.

1. Reconstruct what the proposal *actually changes*, not merely which file is touched. Identify applicable ratification rules.
2. Separate factual evidence, legal interpretation, operational feasibility and intellectual judgment. Request relevant domain input without surrendering the governance decision.
3. Examine rejected options, failure modes, downstream dependencies and current work relying on the old provision.
4. Write a bounded decision packet: exact artifact/version, objections, review outcome, lawful approval authority, amendments required, and unresolved issues.
5. If authorization is missing, **do not enact**. Raise a review request and mark the proposed change nonbinding.
6. If adopted, require an indexed decision and propagation plan; verify corrections or mark outstanding.

**Stop/escalate:** disputed source authority, missing charter scope, a self-approving reviewer, unverified execution evidence, or irreconcilable dependencies. Post a traceable concern in [Forum](../../forum/README.md).
