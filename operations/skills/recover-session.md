# Skill — recover interrupted work from shared records

**Status:** testable prototype. **Input:** repository URL, assigned GitHub Issue/PR (or domain); optional role; no prior chat. **Authority:** any participant may read; edits/decisions require valid permissions.

1. Open [root README](../../README.md), charter, [AGENTS](../../AGENTS.md); identify whether this branch and material are adopted or proposed.
2. Enter assigned domain README, role contract and the canonical Issue. If no Issue exists, inspect [Executive state](../../executive/state/README.md); do not invent one.
3. Read latest issue chronology, handoff, linked evidence/decision records, active PRs and outstanding objections. Distinguish source facts, interpretations and unverified statements.
4. Check whether assigned role still has a holder and authority. If not, publish a blocked/unassigned notice and request Executive routing.
5. Restate in the Issue: currently established, still unknown, source versions, last completed action, blockers, next action, requested review. Avoid duplicate work when another PR is active.
6. Continue only an authorized action, leaving an attributed final checkpoint. If the first five steps are impossible using GitHub alone, record recovery failure with missing input.

**Success:** another participant can follow current state without seeing the former instance's chat. **Do not claim:** automatic restarting or guaranteed identity verification.
