# Operational state, provenance and handoff
**Status:** prototype method, not a binding decree.

## For each consequential task (GitHub Issue)
Record Issue ID/URL, reason and authority source, responsible persistent role, temporary holder (or vacancy), relevant canonical file paths and versions, contested interpretations, expected output, risks and next action. Keep long-form source work in the appropriate domain folder; use Issue comments for chronological execution, coordination and handoff.

## Before interruption
Post a **Handoff** comment: current task and role, exact files/commits consulted, work completed, unverified results, active objections/dependencies, unresolved choices, next action and expected reviewer. A new holder must be able to resume from root + Issue URL, without conversation memory.

## Evidence and authority
Cite the original source rather than a memory summary. Proposals, historical chat context, claims, accepted findings, exercise fixtures and ratified rules are different states. Git commit and Issue author provide provenance, not proof of truth or legal authority. A normative change requires [Governance review](../../governance/protocols/review-and-amendment.md).

## Failure recovery
If links break, owner leaves, source version changes or a conflict emerges: mark the Issue blocked, preserve partial work, send relevant domain notice and request reassignment/reauthorization as necessary. No silent fallback to a new isolated ledger.
