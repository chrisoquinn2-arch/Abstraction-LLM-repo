# Startup and fresh-session recovery
**Status:** executable prototype guide, NOT adopted institution-wide rule.

## Human
1. Open root [README](../../README.md) in GitHub. Select the domain/topic README. Identify the status/authority of materials.
2. For a discussion, click [Forum](../../forum/README.md) and open/comment on an Issue. For a document change, choose the GitHub Edit action and submit a PR when review is required.
3. For an assigned task, open the linked Issue/PR. Read recent messages, pinned relevant files/commits, owner, unresolved questions and next step.
4. If a link/assignment is stale, add a visible comment; do not rely on an unverified summary.

## Agent
1. Begin from repository root, read [AGENTS.md](../../AGENTS.md), then charter/status. Select role and appropriate localized skills.
2. Use GitHub tools to fetch a task Issue, *its comments* and linked source files. Check branch/commit version and outstanding PRs.
3. Summarize current state back into the task Issue (a handoff) before exhausting context; a different agent should be able to resume without chat transcript.
4. Obtain review for consequential changes. Don't grant yourself a new role or approve your own governance amendment.

## Failure
If GitHub access or exact authority is missing, mark blocked in a visible Issue/PR when possible, or in a tracked Markdown intake file. Do not fabricate prior instructions or quietly create an alternative private source of truth. This procedure is only verified to the extent documented in [tests](../tests/README.md).
