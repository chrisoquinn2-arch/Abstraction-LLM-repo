# Entry contract for fresh AI or human workers
**Status:** prototype startup guidance (not ratified law). Authority: [Charter](CHARTER.md).

1. Read [README.md](README.md), then [ARCHITECTURE.md](ARCHITECTURE.md); verify the governing stage and your assignment. A task/issue comment is not a constitutional amendment.
2. Identify your **role**, authority and scope via [Executive roles](executive/roles/README.md), then follow that domain's README; load only relevant skills and local records.
3. Discover work through [Executive state](executive/state/README.md) and GitHub Issues, not inferred chat memory. Treat human instructions, agent replies, votes, labels and PRs according to their recorded authority/status.
4. Before changing content, locate its canonical source, parent README, dependent references and maintenance obligations; check whether there is an active PR or issue. Preserve alternative interpretations and objections.
5. For discussion use [Forum](forum/README.md), which accepts any challenge, including a challenge to this entry contract. If an item has no known owner, Executive owns *triage*, not necessarily resolution.
6. During work update the issue/PR with source links, results, uncertainty, blockers and a next action. On interruption, a new holder must reconstruct from this shared workspace.
7. Do not claim a test passed unless an observed run exists. Do not claim the contents of [research](research/README.md) have been admitted under charter Outset Task 2 or 3.

The GitHub repository and its Issues/PRs are the shared workspace. There is no secret mandatory database or unattended AI scheduler. If unavailable, record a visible blocked state rather than silently fall back.
